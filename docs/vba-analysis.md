## 2. 処理パイプライン

`一括出力.bas` の `一括処理()` が実質的なエントリポイント。

```
[基幹システムからExcelエクスポート]
        ↓ 手作業で貼付
   data シート（49列 × 約900行 / 月）
        ↓ ① リスト表作成()
   リスト表（契約番号でユニーク化 → 得意先名/納品先/住所を引当）
        ↓ ② CreateCompanyList()
   K列に請求先会社名のユニーク一覧（会社名の正規化つき）
        ↓ ③ 請求明細書出力10() / 請求明細書出力8()
   請求明細_10% / 請求明細_8%（ひな形を44行単位で縦に積む）
        ↓ ④ 請求書10_請求明細から抽出() / 請求書8_〜()
   請求書10 / 請求書8（明細書の合計を1行1現場で集約）
        ↓ ⑤ CreatePDFforBill10() / 〜8()
   PDF出力
```

### ④の設計が重要

旧版（`Bill8.bas` / `Bill10.bas`）は data から直接集計していたが、
New版は**明細書シートを走査して集計**している。

これにより **明細書を人が手修正しても請求書が必ず一致する**。
アプリでも「明細が唯一の真実（single source of truth）」という原則として引き継ぐ。

## 3. 分岐構造（移植で最も注意する箇所）

`invoice10.bas` は契約ごとに3分岐する。同じコードが4か所にコピーされており、コード重複の主因。

```vba
MatchingData           = 備品類の行数（ＰＣＡを含まず、値引でもない）
MatchingDataForCounter = カウンタ類の行数（ＰＣＡを含む）

① If MatchingData <> 0 And MatchingDataForCounter =  0   ' 備品のみ
② If MatchingData <> 0 And MatchingDataForCounter <> 0   ' 備品＋カウンタ
③ If MatchingData =  0 And MatchingDataForCounter <> 0   ' カウンタのみ
```

②③では明細書が2枚に分かれ、カウンタ側の納品先名に `　カウンタ` が付く。

**アプリでは `GROUP BY contract_id, billing_group` に置き換わり、この分岐は消滅する。**

### 判定文字列（全角に注意）

```
ＳＲ－ＷＰＥＴ   U+FF33 FF32 FF0D FF37 FF30 FF25 FF34
                 ※ ハイフンは全角 U+FF0D。半角 '-' では一致しない
ＰＣＡ           U+FF30 FF23 FF21
値引             品名に対する部分一致
```

## 4. 金額計算（移植の中核）

### 明細行の金額（Excel数式として埋め込まれる）

```vba
' 列: F=数量  G=基本料  H=単価  I=日数/月数  J=金額
If .Range("I" & row).value <> "" Then
    "=(G" & row & "*F" & row & ")+(H" & row & "*I" & row & "*F" & row & ")"
Else
    "=(G" & row & "*F" & row & ")+(H" & row & "*F" & row & ")"
End If
```

### 明細書の税抜・消費税・合計

```vba
.Cells(r - 34, 10).Formula = "=SUM(J" & sRow & ":J" & lRow & ")"        ' 税抜
.Cells(r - 33, 10).Formula = "=ROUNDUP(J" & (r - 34) & "*0.1, 0)"       ' 消費税（切り上げ）
.Cells(r - 32, 10).Formula = "=J" & (r-34) & "+J" & (r-33)              ' 合計
```

### 請求書の税抜・消費税・合計

```vba
' Bill10New.bas / Bill8New.bas（現役）
beforeTax = Σ（明細書ごとの税抜）
Tax = WorksheetFunction.RoundUp(beforeTax * 0.1, 0)   ' 10%
Tax = WorksheetFunction.RoundUp(beforeTax * 0.08, 0)  ' 8%
TotalAmount = beforeTax + Tax
```

> **切り上げが2回、独立して行われる。**
> 請求書の消費税は「明細書の消費税の合計」ではなく「明細書の税抜の合計」から再計算される。
> 両者は数円ずれうるが、これが現行の挙動。**現行踏襲で確定済み。**

### 単価の優先順位

```vba
If IsEmpty(MonthlyRate) Then
    If SourceData(r, 38) <> "" Then
        単価 = 日単価;    日数 = 経過日数
    Else
        単価 = 販売単価;  日数 = ""
    End If
Else
    単価 = 月単価;        日数 = 月換算
End If
```

## 5. 評価できる実装

移植時にも引き継ぐべき設計判断。

### Range → Variant配列の一括読み込み

```vba
ListData   = wsList.Range("A3").CurrentRegion
SourceData = wsSourceData.Range("A1").CurrentRegion
```

セル単位アクセスを避け、メモリ上でループする定石。

### 数式の遅延一括書き込み

数式を文字列で溜め、ループ終了後にまとめて書く。

### 値ではなく数式を残す

金額欄・小計欄に計算結果ではなく `=SUM(J11:J40)` を書き込む。
**後から人が単価を直せば合計が自動追随する。**

→ アプリでは PostgreSQL の**生成列**として引き継ぐ。

### `Optional showMsg` によるバッチ対応

```vba
Sub リスト表作成(Optional showMsg As Boolean = True)
```

単体実行時はMsgBox、`一括処理` からは `False` で抑制。
**対話モードとバッチモードで同じ関数を再利用する**設計。
